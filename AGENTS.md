# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Commands

- **Build** (compile TypeScript, write `karabiner.json`, regenerate `CHEATSHEET.md` and `hammerspoon/sublayers.json`): `yarn build`
- **Watch** (auto-rebuild on file changes): `yarn watch` — this is always running during development, no need to manually build
- **Cheatsheet** (regenerate `CHEATSHEET.md` only): `yarn cheatsheet` — also runs as part of `yarn build`

## Architecture

This repo generates `karabiner.json` for [Karabiner-Elements](https://karabiner-elements.pqrs.org/) from TypeScript source. The build runs `rules.ts` directly via `tsm` (a TypeScript module runner), which writes `karabiner.json` as a side effect.

### File roles

- **`rules.ts`** — entry point; emits a **single unified profile** (`normalProfile`) and calls `profilesToConfig` to write `karabiner.json`
- **`profiles/`** — `normal.ts` is the assembler; `programming.ts`/`reading.ts`/`trivia.ts` export **mode-gated rule fragments** (not standalone `Profile`s) that `normal.ts` composes into the one profile. `trivia.ts` also exports `gamesSublayer`, the `Hyper+G` games wheel
- **`tmux/`** — `sessions.py`, behind `Hyper+J` (inside iTerm2 in any mode, anywhere in Programming; `profiles/sessions.ts`): `list` prints the live tmux sessions as wheel items with a key each (a letter of the name, else a digit, deterministic for a given set), `go <key>` focuses the iTerm2 window attached to that session (AppleScript, matched by tty) or opens a new window attached to it; `J N` steps to `projects`, the dirs under its `ROOTS` that have a `.envrc` but no session yet, and `new <key>` opens an iTerm2 window `cd`'d there so direnv's `.envrc` creates and attaches the session. The wheel is a **dynamic menu** (below), so what it shows is what the keys do
- **`trivia/`** — `games.json` is the list of daily games (`key`, `name`, `url`, optional HUD `icon`) that `profiles/trivia.ts` builds both `Hyper+G` and Trivia mode's bare keys from. `games.py add` (`Hyper+G =`) turns the frontmost browser tab into a game on the next free key (⌘L ⌘C to read the address, clipboard restored, name prefilled from the window title; on a site that is already a game it offers to remove it) and `games.py remove <key>` is the sublayer's `-` step (`Hyper+G -`, then the game's key; a `steps` entry on the sublayer map, no dialog). Both rebuild afterwards using the node/yarn the login build agent's plist names, so Karabiner and the HUD pick the change up on their own — edit the JSON by hand for anything else
- **`utils.ts`** — helper functions:
  - `createHyperSubLayers(subLayers, extraConditions?)` — builds Hyper key sublayer rules from a declarative map. `extraConditions` is injected into every generated manipulator, used to gate a whole sublayer set behind a mode variable. `LayerCommand` values also support a per-command `conditions` field that gets merged in. Each sublayer's toggle manipulator also sends the which-key HUD `show`/`hide` on press/release (`hudEvent`), and every command inside it (and every direct Hyper command) gets a leading `press` ping (`withHudPress`) so the wheel can light the wedge that fired — it goes *first* in `to` because Karabiner only auto-repeats the last event. A command on the sublayer's own key is a build error (that key is held while you type the command, so it could never fire). A sublayer map can set `hud: false` (the `v` movement layers do) to opt out of both, in which case the press only dismisses whatever wheel is up, and `order: [keys]` to fix the emitted (and so wheel) order — JS puts digit keys first ascending, so the games layer uses it for 1…9, 0. `steps: {key: {description, icon?, commands}}` adds second steps: tapping that key inside the held sublayer flips `hyper_sublayer_<key>.<step>` to 1 and redraws the wheel as the step's menu (`<key>.<step>` in sublayers.json, titled after the step's description), the step's commands shadow the plain ones while it is on, and firing one or releasing the sublayer key clears it. Hyper+G - (remove a game) is the one user. `dynamic: {list, run, keys, description}` (`DynamicMenu`, on a sublayer map or a step) makes a menu whose wedges are computed at show time: the HUD runs `list` (a shell command printing `[{key, code, label, icon?}]`) on every show — `provider` on the menu in sublayers.json — and Karabiner binds each of `keys` to `<run> <key>`, so both sides must assign keys the same way (one script: `tmux/sessions.py`). Generated manipulators are tagged in `HUD_DYNAMIC`; the cheatsheet prints one row for the set and the HUD data an empty `items` plus the `provider`. The Hammerspoon fallback HUD does not run providers. `LayerCommand.icon` / a sublayer map's `icon` (`HudIcon`: `{symbol}` SF Symbol, `{app}` name or path, `{bundle}` id, `{url}` favicon, `{browser: true}` the default browser) override the HUD's inferred wedge icon; they never reach karabiner.json — they're kept in the `HUD_ICONS` WeakMap keyed by the generated manipulator, which cheatsheet.ts reads.
  - `app`, `open`, `window`, `shell` — shorthand `LayerCommand` constructors used inside sublayer maps
  - `little(url)` — open a URL in the floating web card (Arc's Little Arc): a `userCommand({little: {open: url}})` to the overlay agent's `"little"` overlay (`hud/` `LittleOverlay.swift`), a WebKit panel that floats over whatever is in front, native full-screen apps included, and takes the keyboard without activating the agent. ⌘W (so `Hyper+D`) closes it, ⌘O moves the page to the default browser, ⌘R reloads, ⌘[ / ⌘] go back/forward, ⇧⌘C copies the address. It has its own persistent cookie store, and each time it opens `BrowserCookies.swift` first copies Zen's persistent default-container cookies into it (read from a copy of the default profile's `cookies.sqlite` plus its WAL; one way, Zen → card), so the card is signed in wherever Zen is. Session-only, container-tab and partitioned cookies do not come across. Used by the `Hyper+L` lookup layer. Pressing the same lookup again while its card has focus closes it; `littleClose()` (`Hyper+L X`) and `littlePromote()` (`Hyper+L O`) send `{little: "close"}` / `{little: "promote"}`
  - `littleZen(url)` / `littleZenClose()` — the Zen alternative to `little()`, **not bound** (a Zen window cannot float over a full-screen app; the card can). Fires `hammerspoon://little` / `hammerspoon://littleclose`; `littleToggle()` in `hammerspoon/init.lua` runs a second Zen profile (`~/Library/Application Support/zen/Profiles/little`, config in `~/Documents/Programming/librewolf-config/little/`) as its own instance via `open -n -b app.zen-browser.zen --args --profile … --new-window <url>`, sizes each new window to `LITTLE_W`×`LITTLE_H` centered on the mouse's screen, and toggles per URL (focused → close, open → focus, else open). A window filter quits the instance when its last window closes. `littleZenPromote()` (`Hyper+L O`, and Cmd+O while a Little window is focused, via a Hammerspoon hotkey enabled only then) runs `littlePromote()`: reads the address with Cmd+L Cmd+C (clipboard restored), then quits the Little instance and `open -b`s the URL so it can only reach the main Zen; with several Little windows open it closes just that one and sends `-P "Default (release)" --new-tab <url>` instead. Swap `littleZen(` ↔ `little(` in `profiles/normal.ts` to switch between Zen and the WebKit card
  - `browser()` — activate whatever the system default browser is (`Hyper+O G`, Reading `2`): the shell asks LaunchServices for the `https://` handler at keypress, and its HUD icon `{browser: true}` is resolved the same way by the agent. Nothing in the repo names a browser; Raycast browser commands use the Zen extension (`Keyruu/zen-browser`)
  - `keysWheelHold()` — the `LayerCommand` behind `Hyper+Space` in Reading and Trivia: show the mode's `_keys` wheel while held, hide on release (`LayerCommand.to_after_key_up`)
  - `bareKey(key, command, conditions)` — a bare (no Hyper) remap gated by `conditions`, usually a mode's (Reading, Trivia). It gets the same leading HUD press ping as Hyper bindings and its `icon` goes to `HUD_ICONS`, so the mode's auto-shown `_keys` wheel can light the wedge that fired
  - `userCommand(payload)` — a `to` event sending one JSON datagram to the overlay agent (`hud/`) via Karabiner's `send_user_command`; the payload's top-level key picks the overlay. Wrap it per overlay.
  - `hudEvent(message)` — the `to` event every HUD hook uses (`{hud:"show",layer}` / `{hud:"press",code}` / `{hud:"hide"}`). With `HUD_RENDERER = "native"` (default) it's a Karabiner `send_user_command` — one JSON datagram to the user-command socket the `hud/` agent listens on; with `"hammerspoon"` it becomes the `hammerspoon://hud?…` URL event the init.lua wheel understands. Fire-and-forget both ways.
  - `hsEvent(name, params)` — a `to` event that signals Hammerspoon via `open -g "hammerspoon://<name>?…"` (`hs.urlevent`). Fire-and-forget: never waits on Hammerspoon, so it's safe on per-keystroke hooks. `HS_CLI` / `hsCall(lua)` run Lua over `hs.ipc` instead — a **blocking** round-trip, fine for one-off chords (zoom, scratchpad centering) but **never for anything that fires on every key**: clients pile up behind a busy or reloading Hammerspoon
  - **Modes (instant, variable-based — the fast path):**
    - `MODE_NAMES` / `ModeName` — the mode variables (`programming`, `reading`, `trivia`)
    - `switchMode(target)` — flips the target mode variable to 1 and all others to 0, updates `/tmp/karabiner_mode_<name>` flag files, refreshes tmux, fires a notification. **No config reload — instant.**
    - `whenMode(mode)` — conditions that hold only while `mode` is active (gate a mode's rules)
    - `whenNotMode(mode)` — conditions that hold in every mode but `mode`, Normal included (the games wheel, which Programming's Git layer displaces). cheatsheet.ts shows these as "All modes but X"
    - `whenNormal` — conditions that hold only in Normal (all mode vars 0); gates the Normal sublayers
    - `hyperNotHeld` — condition to gate bare-key mode remaps so they don't fire mid Hyper-chord
    - `appAndSwitchMode(appName, mode)` — opens an app and instantly switches into a mode
  - `doubleTap(key, command, delayMs?, extraConditions?)` — fires a command on double-tap of a key
  - `claudeCmd(command)` — types a Codex slash command into the focused terminal + Enter
  - `vimCmd(command)` — escapes to Vim normal mode then runs `:command` + Enter
  - `profilesToConfig(profiles)` — wraps profiles in a `KarabinerConfig`, applies `keyboard_type_v2: "ansi"` and marks the first profile `selected`
- **`types.ts`** — TypeScript interfaces mirroring the Karabiner JSON schema (`KarabinerConfig`, `Profile`, `KarabinerRules`, `Manipulator`, `KeyCode`, etc.)
- **`cheatsheet.ts`** — walks the assembled `normalProfile` (conditions + descriptions) and renders `CHEATSHEET.md`, grouping bindings by mode. Run via `yarn cheatsheet` or automatically on `yarn build`. `CHEATSHEET.md` is generated output — never edit it by hand. It **also emits `hammerspoon/sublayers.json`**: for each runtime mode (normal/programming/reading/trivia) the *effective* contents of every Hyper sublayer plus a `_top` map of the Hyper layer itself (sublayer keys flagged `group`, then direct commands), plus `_keys` for a mode's bare-key bindings (Reading, Trivia), which the agent shows unprompted when the mode is entered. Resolution is first-match-wins in rule order, mirroring Karabiner precedence, so mode overrides (e.g. Programming's `O G` = Godot) win. App-gated bindings (`frontmost_application_if`) carry their bundle-id regexes as `app`, and a key keeps every app-gated candidate until an un-gated one settles it, so the HUD can resolve per frontmost app at draw time. Every item also carries its raw key_code as `code`, which is what the `press` ping names, and usually an `icon` — explicit (`HUD_ICONS`), else inferred from the events: a known key (`volume_increment` → `speaker.wave.3.fill`, plain ⌘C/V/Z/F/W/Q/T), `open -a` / `open /path.app` → `{app}`, `raycast://` → `{bundle: com.raycast.macos}`, a web URL → `{url}` (the renderer fetches the site's favicon via Google's s2 service into `~/Library/Caches/karabiner-hud/favicons/<host>.png`, showing `globe` until it's cached; localhost stays `globe`). Items with an app or site icon drop their leading "Open " (HUD label only; the cheatsheet keeps its wording). HUD pings (`send_user_command`, `hammerspoon://hud`) are skipped when humanizing actions. This feeds the radial which-key HUD and is generated output too — never hand-edit.
- **`iterm/`** — floating nvim windows, implemented as iTerm dynamic profiles (symlinked into `~/Library/Application Support/iTerm2/DynamicProfiles/` by `setup.sh`) plus per-window nvim overlay lua:
  - `scratchpad.json`/`scratchpad.lua` — `Hyper+E`: self-clearing scratch buffer on `~/scratch.md` (wipes on open + after 5 idle minutes), diagnostics/spell/lint disabled, autosave on focus loss
  - `ideas.json`/`ideas.lua` — `Hyper+I`: fresh timestamped idea per summon, committed to the Obsidian vault Ideas folder on focus loss; untouched buffers are never written
  - `todo.json`/`todo.lua` — `Hyper+T`: single persistent `todo.md` in the Obsidian vault root, autosaved on focus loss, reloaded from disk on re-summon so Obsidian edits sync in. Not cleared, not per-summon.
  - Karabiner sends F18/F19/F20 to summon; Hammerspoon's `hotkeyCenter(title)` centers the window. **Reload after editing a profile JSON with `touch -h` on its DynamicProfiles symlink** — deleting/recreating the symlink makes iTerm silently drop the hotkey registration.
- **`hammerspoon/init.lua`** — besides per-app mode auto-switching and floating-window centering (`hotkeyCenter`), exposes `zoom(dir)`: synthesizes a real pinch-magnify gesture via `hs.eventtap.event.newGesture("beginMagnify"/"endMagnify", amount)` (the only way to inject a trackpad gesture — no public API exists). Gesture-blind apps (Chromium/Electron, listed in `GESTURE_BLIND`) fall back to ⌘=/⌘−. Karabiner's `Hyper+=`/`Hyper+-` call it via `hs -c "zoom('in'/'out')"`. Tune `ZOOM_STEP`. It also hosts the **fallback radial which-key HUD** (active only with `HUD_RENDERER = "hammerspoon"` in utils.ts; the default renderer is `hud/`): `hudShow(key)` / `hudHide()` are reached from Karabiner via `hammerspoon://hud?show=<key>` / `?hide=1` (`hs.urlevent`, fire-and-forget — every sublayer toggle on press/release; Caps Lock sends `show=_top`). After a `HUD_DELAY` (400ms) hold it draws an `hs.canvas` GTA-style weapon wheel of that sublayer's commands from `sublayers.json`, mode-aware via the `/tmp/karabiner_mode_*` flags: a dimmed screen, a thick ring cut into one wedge per command (annular-sector polygons via `segments`, so no dependence on canvas arc angle conventions), key letter big in accent over the label, title + mode in the hub. >10 items split into two rings (top level: sublayers inner with a warm tint, direct commands outer). All geometry is a fraction of the outer radius `R = HUD_SIZE × min(half-width, half-height)`; the `HUD_*` constants at the top of the block tune size, ring proportions, gaps, colours and font sizes. Fast chords never see it; if a wheel is already up, switching sublayers is instant. Items tagged `app` are filtered against the frontmost app's bundle id (`visibleItems`), first match per key, so WhatsApp's `Hyper+H/J/K` only appear inside WhatsApp. Each item carries its raw `code`; `hudPress(code)` (from `?press=<key>`, sent as a command fires) restyles that wedge white with dark text in place for `HUD_FLASH` (100ms), and `hudHide` defers while a flash is running so a quick chord still shows what was hit. `sublayers.json` is re-read on every show because the pathwatcher only reloads on `.lua` changes.
- **`hud/`** — the **overlay agent**, a Swift package (AppKit + Core Animation, no Dock icon) built by `setup.sh` and kept alive by the `com.karabiner-config.hud` LaunchAgent (log: `/tmp/karabiner-hud.log`). It binds Karabiner's user-command socket (`/Library/Application Support/org.pqrs/tmp/user/<uid>/user_command_receiver.sock`, UNIX datagram, via the `KarabinerElementsUserCommandReceiver` package); `Router` (`Overlay.swift`) hands each JSON payload to the overlay registered under its top-level key. Two today: `"hud"`, the **native which-key HUD**, handling `{hud:show|press|hide}`, and `"little"`, the floating web card (`LittleOverlay.swift`, `{little:{open:url}}` / `{little:"close"}`). **Adding an overlay:** a type conforming to `Overlay` (draw into an `HUDWindow`, animate with `Drawing.swift`'s `cut`/`animate`/`textLayer`), `router.register("<key>", …)` in `main.swift`, and a typed wrapper over `userCommand({ <key>: … })` in `utils.ts` for bindings to call; `swift build`, then `launchctl kickstart -k gui/$UID/com.karabiner-config.hud`. Files: `main.swift` (args: `--data <sublayers.json>`, `--socket`), `Overlay.swift` (protocol + router), `Drawing.swift` (shared CA helpers), `HUDController.swift` (state machine: hidden → pending → full → quiet; a press during the 400ms hold makes the wheel appear already quiet; hide waits for a running 100ms lit flash but cuts a running step-back), `Wheel.swift` (layer tree: radial vignette, rings of `WedgeLayer`s, hub; `appear`, `enterQuiet`, `setLit`), `Model.swift` (JSON, `/tmp/karabiner_mode_*`, `visible` app filtering, `provided` runs a dynamic menu's provider command and decodes its items, `rings`: ≤10 items one ring, else groups inner / direct outer, else digits inner / rest outer when both fit, else halves), `Icons.swift` (SF Symbols tinted white/accent, app icons via `NSWorkspace`, favicons fetched + cached on disk), `HUDWindow.swift` (click-through non-activating panel over full-screen apps, `moveToActiveSpace` rather than `canJoinAllSpaces` because a join-all panel once shown over a native full-screen app stays bound to that Space and later draws land where nobody looks — the controller also recreates the panel if it still ends up off the active Space; `Theme.material` blur experiment; the app itself ignores hide, since a "Hide Others" in any app would otherwise leave every wheel drawing into a hidden app), `Theme.swift` (every number: `size` 0.70 R, ink/accent, type sizes, `holdMs` 400, `litMs` 100, `quietMs` 140, `quietScale` 0.60). Re-reads sublayers.json on every show. `ModeWatcher.swift` watches the `/tmp/karabiner_mode_*` flags: entering a mode that has a `_keys` menu draws that wheel with no hold (`modeChanged`), lingering `keysMs` (2.5 s) or until the first bare key lights its wedge, and the Hyper release that follows the switch chord is ignored while it is up. Test without a keyboard: send a datagram, e.g. `python3 -c 'import socket,json;s=socket.socket(socket.AF_UNIX,socket.SOCK_DGRAM);s.sendto(json.dumps({"hud":"show","layer":"s"}).encode(),"<socket>")'`; `screencapture -x` sees the panel.
- **`indicators/`** — mode indicators: `karabiner-profile.2s.sh` (SwiftBar plugin, symlinked by `setup.sh`) and `tmux-status.conf` (snippet to append to `~/.tmux.conf`)
- **`setup.sh`** — idempotent installer: dependency checks, path personalization (repo location + brew prefix), all symlinks (with backups), login-build LaunchAgent (`com.karabiner-config.build`), native HUD build + LaunchAgent (`com.karabiner-config.hud`), initial build

### Modes (why one profile, not four)

Profile switching (`karabiner_cli --select-profile`) reloads the entire config and is slow (~1–2s, drops keystrokes). Instead there is **one profile** and "modes" are just variables gated with `variable_if` conditions, so switching is an instant variable flip. Mode-specific keys (including bare keys like Trivia's `1` or Reading's `→`) are gated so they only apply in their mode; when no mode is active, keys behave normally.

Switching conventions (all via the common, ungated `m` sublayer — works from any mode):
- **→ Programming**: `Hyper + M, P`
- **→ Reading**: `Hyper + M, R`
- **→ Trivia**: `Hyper + M, T` — the games are bare keys (`1`–`0`, `a s d f g q w e r`, `x` closes the tab). Entering the mode shows them as a wheel on its own (the mode's `_keys` menu: digits inner ring, letters outer, favicons); it lingers 2.5 s or until the first game key lights its wedge; hold `Hyper + Space` to bring it back. The same games are also a Hyper sublayer, `Hyper + G` (every mode but Programming), with `=` to add the frontmost tab as a game and `-` then a game key to remove it, all inside the chord — see `trivia/`
- **→ Normal**: `Hyper + M, N`

Auto-switching by app is handled by Hammerspoon (`hammerspoon/apps.lua` + `init.lua`), which sets the same mode variables (mutually exclusive). Indicators read the `/tmp/karabiner_mode_*` flags: the SwiftBar plugin and tmux status snippet, both in `indicators/`.

### Adding a new mode

1. Add the mode name to `MODE_NAMES` in `utils.ts` (and `MODE_LABELS`)
2. Create `profiles/<mode>.ts` exporting a gated `<mode>Rules: KarabinerRules[]` — wrap Hyper sublayers with `createHyperSubLayers({...}, whenMode("<mode>"))`, and bare-key manipulators with `conditions: [...whenMode("<mode>"), hyperNotHeld]`
3. Import the fragment in `normal.ts`, spread it into the rules array, and add `<key>: switchMode("<mode>")` to the `m` sublayer
4. Add the mode to `allModes` in `hammerspoon/apps.lua` (and an app mapping if it should auto-switch), and to the indicators (`karabiner-profile.2s.sh`, `~/.tmux.conf`)

### Key concept: Hyper Key sublayers

`createHyperSubLayers` takes a map of `KeyCode → HyperKeySublayer` (or a `LayerCommand` directly). Each sublayer is activated by holding Hyper (Caps Lock remapped to ⌃⌥⇧⌘) then pressing the sublayer key, after which a second key triggers the bound command. The function generates all the variable-setting manipulators and conditions automatically.
